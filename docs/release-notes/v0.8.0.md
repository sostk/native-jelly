# v0.8.0 — Native Jelly: the first release, a native Jellyfin client

This is the first release of Native Jelly, a native Jellyfin client for LG webOS televisions. It is built from PlxNative 0.7.0, rebuilt to sign in to and play from your own Jellyfin server.

## Coming from PlxNative: this is a separate app

Native Jelly installs as its own app, **com.sostk.nativejelly**, beside PlxNative rather than over it. It does not read PlxNative's sign-in, profiles or settings, and it does not connect to Plex servers. Installing it changes nothing in PlxNative; uninstall that separately if you no longer want it.

## If your server uses http: your password is sent unencrypted

A server reached as http:// (for example a home server at its local address) receives your Jellyfin password, and afterwards your sign-in token, without encryption, so anyone able to watch traffic on that network can read them. Native Jelly never does this on its own: it asks **Connect without encryption?** once for that server, with a stronger warning when the address is on the internet.

**What to do:** use your server's https:// address when it has one. If you allow an http server, **Settings → Unencrypted connections** lists it and turning it off stops Native Jelly using it at once.

## What's new

- **Sign in to your Jellyfin server.** Type its address, then sign in with your user name and password, or with a Quick Connect code approved from another device signed in to Jellyfin. The last server you used stays under **Recent** after you sign out.
- **Several people on one television.** Up to twelve Jellyfin users can stay signed in; with more than one, the app opens on **Who's watching?**. The account menu offers Switch user, Add user (which lists the users your server shows on its own sign-in screen) and Sign out of one user without touching the others. Pins, recent searches, sort choices and subtitle offsets are kept per user. A user whose sign-in has expired is asked to sign in again. Each kept user's sign-in token stays on the television until that user signs out or you choose **Delete all local data**; their password is never stored.
- **Your Jellyfin libraries, Home, Search and Continue Watching** in the native interface PlxNative used.
- **Playback that follows your server's decision.** A file the television can decode plays directly; anything else is remuxed or transcoded by your server. Your server sees what is playing, where you stopped and what you finished, so resume points and watched status match your other Jellyfin apps.
- **Choose audio and subtitles before you press Play**, and pick between versions of a film when your library has more than one.
- **Subtitles survive a transcode.** A subtitle you chose stays on when the server converts the video, delivered the way the server sends it; one the app cannot draw is asked for again as part of the picture.
- **Subtitle timing, size and position** can be changed in the player, and a timing offset is remembered for the next time you play the same item. Styled ASS and SSA subtitles keep their styling when a video plays directly.
- **Spanish and Belarusian** join English, following the television's language setting.

## Fixed

- **A transcoded video showed no total length**, so its position bar and time remaining were empty. It now shows the length of the whole film, including after a resume or a seek.

## Compatibility

- **Plays video, verified by watching it — 2021 LG sets.** One television: an LG OLED65C1PTB running webOS 6, on which a few videos were watched from a Jellyfin 12 server using a development build of this release.
- **Starts, and nothing further is known — every other firmware from webOS 4.0 up.** The release run checks this binary's libraries and symbols against every firmware image webosbrew has from platform release 4.4.2 up, and fails if any of them would refuse to start it; webosbrew has no image of platform releases 4.0 to 4.4.1, so those are expected to start but were not checked; the matrix is in the [technical audit](https://github.com/sostk/native-jelly/blob/main/docs/release-audits/v0.8.0.md). That grades startup and says nothing about whether video plays.

No one else has reported running Native Jelly yet. Reports from PlxNative do not carry over: it is a different app talking to a different server. If you try it on any set, [tell us what happened](https://github.com/sostk/native-jelly/issues). It working is as useful a report as it failing.

## Known issues

- **Playback can fail from a server reached over https through a reverse proxy**, while the same server plays when reached over http on the home network. Seen on the maintainer's own server; this release does not fix it.
- **Re-encoding is always H.264**, even when your server is allowed to encode HEVC, because the app cannot read that setting.
- **Live TV is not supported.**

## Help test this release

**If your server is reached through a reverse proxy over https**, try a film that plays directly and one that needs a transcode, and tell us which played. **If your television is not a 2021 set**, any playback at all is new information. [Open an issue](https://github.com/sostk/native-jelly/issues). It working is as useful a report as it failing.

## Installing

Download **com.sostk.nativejelly_0.8.0_arm.ipk** and install it with the [Homebrew Channel](https://github.com/webosbrew/webos-homebrew-channel) or [dev-manager-desktop](https://github.com/webosbrew/dev-manager-desktop). You do **not** need a rooted TV.

Nothing in this distribution chain is signed, so this sha256 is what tells you the file you have is the file published here:

```
__IPK_SHA256__  com.sostk.nativejelly_0.8.0_arm.ipk
```

[Installing and checking a download](https://github.com/sostk/native-jelly/blob/main/docs/install-and-verify.md) covers the other assets, how to check the hash on each platform, and the Developer Mode expiry that uninstalls your apps. Crash reports and usage analytics are both off until you choose to share them; what each contains is in the [privacy policy](https://github.com/sostk/native-jelly/blob/main/PRIVACY.md). This package bundles FFmpeg under LGPL-2.1-or-later and its complete corresponding source is attached to this release. Exactly what was built, verified and shipped is in the [technical audit for v0.8.0](https://github.com/sostk/native-jelly/blob/main/docs/release-audits/v0.8.0.md).
