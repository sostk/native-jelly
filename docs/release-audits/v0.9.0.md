# Release audit — v0.9.0

The evidence behind [the v0.9.0 release note](https://github.com/sostk/native-jelly/blob/main/docs/release-notes/v0.9.0.md). **Draft, prepared 2026-10-26:** the notes compare `v0.8.0` with `main` at `133c1de1`. This document does not record a completed release run. The generated block must be populated from the actual release artifacts by CI.

## Device test evidence

No new television session, playback suite, performance suite or package installation was performed while drafting these documents. No v0.9.0 release artifact was built or watched for this audit.

The [v0.8.0 audit](https://github.com/sostk/native-jelly/blob/main/docs/release-audits/v0.8.0.md) records development-build playback on an LG OLED65C1PTB (C1, 2021), platform release 6.5.3, firmware 03.53.45, against Jellyfin 12. It includes converted video with a subtitle sidecar, seeking and track changes. Those observations remain evidence about the earlier builds only.

The AV1 and VP9 commits port implementation and some measurements from PlxNative. In particular, `e6d9428b` says AV1 was not verified on an AV1 set; `0cd3ab36`, `e1e0c8a5` and `89ef840c` describe upstream VP9 measurements. They do not establish Native Jelly playback from Jellyfin on those sets. `docs/webos5-port.md`, under “The public Seek”, explicitly leaves webOS 5+ device behavior unverified. Its separate sentence about a 2016 set playing is not used as Native Jelly compatibility evidence here.

Before publication, record the exact built revision, app flavour, television, firmware, server, date and observed results for AV1/VP9 playback, native seeking, Dolby Vision with copied video, DTS routing, frame rate during audio conversion and end-of-stream handling. Host tests and static loader checks cannot establish picture output.

## Compatibility tiers, and what moved

No playback tier moves in this draft. The earlier C1 observations are attributed to v0.8.0's development builds. Static firmware compatibility for v0.9.0 is pending the release run and belongs in the generated block; no previous firmware matrix is copied into this audit.

AV1 and VP9 are offered only when a device codec row is present, subject to the advertised bounds and routing rules (`9349fbb9`). VP9's 10-bit claim is limited to the older video path; webOS 5+ remains capped at 8-bit (`89ef840c`). AV1 Dolby Vision is not offered. The webOS 3.x runtime-symbol changes do not establish a new supported minimum, and the notes make no new claim for those sets.

## Known issues at release, with provenance

- **HTTPS through a reverse proxy:** carried from the maintainer's observations recorded in the v0.8.0 audit. The media reader and proxy problem were not addressed in this range; no new reproduction was performed for this draft.
- **H.264 re-encoding:** `docs/jellyfin-playback.md` records why Jellyfin's encoder setting is not read. Adding AV1 and VP9 as video-copy options does not add server encoding in those formats.
- **New codec and seek paths need device evidence:** the implementation and limitations are described above. VP9 HDR10 uses the older ACB path; it does not establish VP9 HDR playback on webOS 5+. AV1 decoder framing and native seek picture continuity remain unverified for this release.
- **Auto quality away from home:** the prior audit's HLS concerns are not settled by these changes. Do not infer that this path is verified from direct-play or progressive-conversion fixes.
- **Progressive-transcode EOF:** the previous audit records a loopback transport-EOF issue. `a6893480` handles the television pipeline's end-of-stream signal; it is not evidence that the separate HTTP-reader issue is fixed.
