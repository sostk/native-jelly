# Release audit — v0.11.0

The evidence behind [the v0.11.0 release note](https://github.com/sostk/native-jelly/blob/main/docs/release-notes/v0.11.0.md). Written for a webosbrew reviewer, a contributor auditing an old release, and us in a year. The section at the bottom is generated from the artifact that was published; everything above it was written by a person before the release ran.

**Prepared 2026-11-28** against `main` at `d181bb2a`, compared with `v0.10.0` (21 commits, including contributor PRs #40, #45, #46 and #48; #46 landed as three commits with its author kept).

Changes in this release that were **not** observed on a television here:

- The on-TV AC-3 conversion (`3ccdb3f5`) was played on the set during its own development (recorded in the maintainer's notes: TrueHD 7.1 Atmos converted and played); it was not re-run on the integrated tree.
- User pictures (`a8113639`, #45): reviewed and host-tested here; not watched on the set.
- DTS-HD 7.1 by its core (`0c4cef02`), audio fed past a backpressured video sink (`562cd2c7`), the Dolby Vision IDR-only landing (`a22e8cab`), `/usr/lib/os-release` fallback (`171bfb65`), UTF-8-safe truncation (`9f13922f`): host tests and the ARM build only. The Dolby Vision change is a port of upstream PlxNative's fix and was not reproduced on the C1.
- DB8 state move (`268083c2`, #40): host tests only. Not yet verified on a device: a record under the old `plxstate.*` id moving to `njstate.*`, and DB8 find over a private kind with no indexes and del with purge on webOS 4.
- Audio & subtitles preferences (`fc89165c`) and Mixed / Home Videos / Music Videos libraries (`f2f2fa1e`, `116bff91`): verified in the Linux simulator against `tests/mock_jf.py`, not on the set.
- TLS session cache off in key mode (`5be1902f`): host tests in an Ubuntu 26.04 container (libcurl 8.18); which television firmwares carry a libcurl that resumes sessions this way is not known.
- Listening: the lossless routes were graded by the decoder LG allocated, burst counters and playback speed. The soundbar's display and the audio were not checked by ear for this audit.

## Compatibility tiers, and what moved

- **Plays video, verified:** unchanged — the one 2021 LG C1 (platform 6.5.3).
- **Plays video, reported:** the 2021 line now cites Mokto's C1 report for the lossless routes. Nothing is promoted: therolla's and watsonmaster's reports are failures of one file shape.
- **Starts:** regenerated by the release run below; no matrix is copied in by hand. This release exports `ioctl` from the executable (`src/es_swap.c`); `ci/check-elf.sh` asserts the export, and the hook forwards every call untouched except on webOS 6 while a playback has armed the carrier.

## Known issues at release, with provenance

- **Dolby Vision Profile 8 + Atmos direct play stops after about 45 s:** #36, reported on a C3 (11.2.0), an SM8500 (4.10.2) and a C1 (6.5.3). Not reproduced here; not changed in this range.
- **Server address with a path:** #42; `jf::address::candidates` drops the path and `Origin` has no base path. Not changed.
- **HTTPS through a reverse proxy:** carried from the v0.8.0 audit; not addressed or re-tested.
- **H.264 re-encoding:** unchanged; `docs/jellyfin-playback.md` records why.

## Deliberately not done

- No television check of the release package, and no full device suite on the integrated tree. Install the published `.ipk` on the C1 (cut-release step 6) before announcing it.
- **Documentation screenshots were not regenerated.** `make screenshots` builds the macOS simulator and this release was prepared on Linux. The README and listing screenshots predate the new Settings rows and user pictures.
- **This release can write outside the app's own directories and contact a new host, only on explicit request**, and the note carries an action-required section for it: the HBR install downloads two files from `raw.githubusercontent.com/sostk/native-jelly/4efd65aab44e34c4a8cfc54c14eb065639f60561/companion/hbr/earc_route/…`, checks each against a SHA-256 compiled into the binary (`player/hbr_support.rs`), and runs `nativejelly-hbr.sh install` as root through Homebrew Channel's `exec`, which re-checks the root-owned copies before loading; it writes `/var/lib/webosbrew/nativejelly-hbr/`, `/var/lib/webosbrew/init.d/nativejelly-hbr` and `/dev/earc_route` in the `com.sostk.nativejelly` and `com.sostk.nativejelly.debug` sandboxes, and a staging directory under the runtime root that it removes. No other new outbound host, listener, FIFO or credential sink was added in this range. The kernel module itself (GPL-2.0-only) is not in the package; its complete source is in `companion/hbr/earc_route/` at the pinned commit.
- The listening check for the lossless routes was not done by ear.
- The `make build-bench` table owed for #46's Makefile change (one `--export-dynamic-symbol`) was not recorded.
- The Homebrew Channel listing (`docs/webosbrew-package.yml`) is updated in this commit; the PR to `webosbrew/apps-repo` follows the published release.

## Release configuration

| | |
|---|---|
| flavour | `com.sostk.nativejelly` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK `webos-d7ed7ee.6` (unchanged), Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable (unchanged) |

Unusual for this build:

- **FFmpeg gained decoders and an encoder** for the on-TV AC-3 conversion (`3ccdb3f5`): the lossless/raw audio decoders (TrueHD/MLP, FLAC, ALAC, Vorbis, PCM), the mlp and flac parsers and the `ac3` encoder. Same FFmpeg version and library majors.
- **The executable exports `ioctl`** (`-Wl,--export-dynamic-symbol=ioctl`) for the DD+ carrier.
- **No new payload files:** the carrier's silent E-AC-3 frame (`silent-eac3.bin`) is compiled into the binary.
- **New embedded text:** `companion/hbr/nativejelly-hbr.sh` is compiled into the binary as the HBR installer.
